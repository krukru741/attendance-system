# Biometric Module

## 1. Goal

Provide secure fingerprint enrollment, verification, device management,
and biometric synchronization.

## 2. Enrollment UX

``` text
Select Employee
  ↓
Select Finger
  ↓
Connect Scanner
  ↓
Capture Sample 1
  ↓
Capture Sample 2
  ↓
Capture Sample 3
  ↓
Validate Quality
  ↓
Generate Template
  ↓
Encrypt / Store Template
```

## 3. Enrollment Screen

Display:

-   Employee name
-   Employee ID
-   Selected finger
-   Scanner status
-   Fingerprint quality
-   Current capture sample
-   Instructions
-   Cancel
-   Save biometric

## 4. Finger Options

-   Left Thumb
-   Left Index
-   Left Middle
-   Left Ring
-   Left Little
-   Right Thumb
-   Right Index
-   Right Middle
-   Right Ring
-   Right Little

## 5. Storage

Prefer biometric templates generated by the vendor SDK rather than raw
fingerprint images.

Recommended fields:

``` text
EmployeeBiometric
-------------------------
Id
EmployeeId
FingerType
Template
TemplateFormat
DeviceId
CreatedAt
UpdatedAt
IsActive
```

Protect biometric data using encryption and strict access controls.

### 6.2 BiometricLog Entity

`BiometricLog` records raw device-level activity — connection attempts,
sync operations, and pushed/pulled events — separately from
`AttendanceEvent`, which represents an actual scan tied to an employee.
This keeps device diagnostics traceable without mixing them into
attendance history.

``` text
BiometricLog
-------------------------
Id
DeviceId
LogType
Message
RawPayload
Success
Timestamp
CreatedAt
```

Possible `LogType` values:

-   CONNECTION_TEST
-   SYNC
-   PUSH_USER
-   PULL_LOGS
-   ERROR

### 6.3 Lifecycle / Usage

``` text
Device Registered
  ↓
Test Connection → BiometricLog (CONNECTION_TEST)
  ↓
Sync → BiometricLog (SYNC) → AttendanceEvent(s) created from pulled logs
  ↓
Push User (enroll/update on device) → BiometricLog (PUSH_USER)
  ↓
On failure → BiometricLog (ERROR), Device status updated
```

`BiometricDevice.Status` should be updated based on the most recent
connection/sync result, and failures should always be written to
`BiometricLog` rather than silently discarded, consistent with the
offline-sync failure handling in `14-OFFLINE-SYNC.md`.

## 7. Device Abstraction

Create an interface:

``` csharp
public interface IBiometricDevice
{
    Task<bool> ConnectAsync();
    Task DisconnectAsync();
    Task<BiometricTemplate> EnrollAsync();
    Task<BiometricMatchResult> VerifyAsync();
    Task<IReadOnlyList<BiometricAttendanceEvent>> GetAttendanceLogsAsync();
}
```

Use adapters for each biometric brand/SDK.
